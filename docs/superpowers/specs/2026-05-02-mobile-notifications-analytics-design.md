# Mobile Deployment, Push Notifications & Analytics — Design Spec

**Date:** 2026-05-02  
**Status:** Approved

---

## 1. Overview

Three related capabilities added to JobTrack AI:

1. **Mobile delivery** — PWA (web install) + Google Play Store via Capacitor Android wrapper
2. **Push notifications** — new match alerts (score ≥ 60) + interview stage reminders
3. **Analytics** — pipeline health dashboard + match quality trend charts

These are implemented sequentially. PWA/Capacitor provides the delivery layer that push notifications depend on. Analytics is independent and can be built in parallel or after.

---

## 2. Mobile Delivery (PWA + Capacitor)

### Approach

Capacitor wraps the deployed Next.js web app using `server.url` — the Android APK loads the live Vercel/Railway URL in a WebView. No static export required, so server components, SSR, and the existing auth flow all work unchanged.

PWA support is added directly to the Next.js app to enable browser-based install on Android Chrome and to provide the service worker foundation for web push notifications.

### PWA

**Files added to `web/public/`:**
- `manifest.json` — app name, short name, icons, `display: "standalone"`, `theme_color`, `background_color`
- `sw.js` — service worker: cache-first for static assets, network-first for API calls, push event handler (forwards to notification display)
- `icons/icon-192.png`, `icons/icon-512.png` — app icons

**`web/app/layout.tsx` changes:**
- Add `<link rel="manifest" href="/manifest.json" />` in `<head>`
- Add `<meta name="theme-color" content="#0f0c1a" />`
- Client component `<ServiceWorkerRegistration />` that calls `navigator.serviceWorker.register('/sw.js')` on mount

### Capacitor

**Setup (inside `web/`):**
- `capacitor.config.ts` — `appId: 'com.jobtrack.ai'`, `appName: 'JobTrack AI'`, `webDir: 'out'` (fallback), `server.url` pointing at production URL
- `android/` folder generated by `npx cap add android` — gitignored except `android/app/google-services.json` (kept but not committed; added via CI secret)

**Build flow:**
1. Deploy Next.js to Vercel/Railway
2. `npx cap sync android`
3. `cd android && ./gradlew assembleRelease`
4. Upload signed APK/AAB to Google Play Console

**Local dev:** `server.url` can be overridden via env var (`CAPACITOR_SERVER_URL`) to point at `http://10.0.2.2:3000` (Android emulator localhost alias).

## 3. Push Notifications

### Database

New table `push_tokens`:
```sql
CREATE TABLE push_tokens (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  token       TEXT NOT NULL,
  platform    TEXT NOT NULL CHECK (platform IN ('android', 'web')),
  created_at  TIMESTAMPTZ DEFAULT NOW(),
  updated_at  TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (user_id, token)
);
ALTER TABLE push_tokens ENABLE ROW LEVEL SECURITY;
CREATE POLICY "users manage own tokens" ON push_tokens
  FOR ALL USING (auth.uid() = user_id);
```

### Firebase Setup

- One Firebase project: `jobtrack-ai`
- FCM enabled
- `google-services.json` → `android/app/` (Capacitor Android)
- VAPID public key generated in Firebase Console (Web Push certificates) → stored as `NEXT_PUBLIC_FIREBASE_VAPID_KEY` in the Next.js app (prefix makes it available client-side)
- `firebase-admin` service account JSON → `FIREBASE_SERVICE_ACCOUNT_JSON` env var on Railway (Admin SDK handles FCM signing; no separate VAPID private key needed)

### API

**New file: `api/src/services/push.ts`**
```
sendPush(userId, title, body, data?) → void (fire and forget)
  1. SELECT token, platform FROM push_tokens WHERE user_id = userId
  2. For each token, send FCM message via firebase-admin
  3. On error code token-not-registered / invalid-registration-token → DELETE token from push_tokens
```

**New route: `POST /notifications/register`**
- Auth required
- Body: `{ token: string, platform: 'android' | 'web' }`
- Upserts into `push_tokens` (update `updated_at` on conflict)

### Frontend

**New component: `web/components/push/PushSetup.tsx`** (client component)
- Mounted once in `web/app/(app)/layout.tsx` (inside authenticated routes)
- Flow:
  1. Check `Notification.permission`
  2. If `'default'`: show a subtle banner "Enable job alerts?" with an Allow button
  3. On Allow: request permission
  4. If granted on Capacitor (Android): call `PushNotifications.register()`, listen for `registration` event to get FCM token
  5. If granted on web: call `pushManager.subscribe({ userVisibleOnly: true, applicationServerKey: NEXT_PUBLIC_FIREBASE_VAPID_KEY })`; store `JSON.stringify(subscription)` as the token (the full object — endpoint + p256dh + auth keys — is required for FCM web push delivery)
  6. POST token + platform to `POST /notifications/register`
- Does not re-register if a token for this device already exists in localStorage

### Notification Triggers

**Trigger 1 — New match ≥ 60** (`api/src/workers/matchEngine.ts`):
- After Phase 1 upsert: if `phase1.score >= 60`, call `sendPush(userId, "New match: ${job.title}", "${job.company} — ${phase1.score}% match")`
- After Phase 2 update: if `output.refined_score >= 60 && phase1.score < 60` (score crossed threshold via AI refinement), also send

**Trigger 2 — Interview stage** (`api/src/routes/applications.ts` or wherever status updates are handled):
- When `status` is updated to `'interview'`, call `sendPush(userId, "Interview reminder", "${job.title} at ${job.company} — don't forget to prepare!")`

## 4. Analytics

### Page

New route: `web/app/(app)/analytics/page.tsx` — async server component, queries Supabase directly.

### Pipeline Health Section

Four stat cards (same visual style as dashboard StatWidgets):
- **Jobs this week** — `COUNT(*) FROM jobs WHERE created_at >= NOW() - INTERVAL '7 days'`
- **Matches this week** — `COUNT(*) FROM job_matches WHERE user_id = userId AND computed_at >= NOW() - INTERVAL '7 days'`
- **AI refined rate** — `COUNT(*) WHERE ai_refined = true / COUNT(*) * 100` (last 30 days)
- **Avg match score** — `AVG(match_score) FROM job_matches WHERE user_id = userId`

Sparkline: jobs scraped per day for last 30 days — small area chart below the cards.

### Match Quality Section

Two charts side by side:

**Score distribution (bar chart):**
- Buckets: Low (0–39), Good (40–59), Strong (60–79), Excellent (80–100)
- Uses `match_score` from `job_matches` for current user
- Colors match dashboard accent colors: red/yellow/purple/green

**Average score over time (line chart):**
- `AVG(match_score)` grouped by ISO week, last 12 weeks
- `job_matches WHERE user_id = userId AND computed_at >= NOW() - INTERVAL '84 days'`

### Chart Library

**Recharts** — already a common React charting library; if not installed, add `recharts` to `web/package.json`. No canvas, pure SVG, composable components.

### Navigation

Add "Analytics" link to the sidebar navigation (`web/components/layout/Sidebar.tsx` or equivalent), between Jobs and Tracker entries.

## 6. Out of Scope

- iOS / App Store (no Capacitor iOS target)
- In-app notification centre / notification history
- Scheduled interview reminders (requires interview date field — not in current schema)
- Email notifications
- Push notification preferences screen (all notifications on by default; can be suppressed via OS settings)
